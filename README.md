# $bog_selection

Плагин: Ctrl+A (на маке Cmd+A) выделяет ближайший к каретке вид с исходным текстом и кладёт в буфер этот исходник, а не отрисованное. Ctrl+C следом отдаёт то же самое.

Вешается один раз на корень приложения:

```tree
$my_app $mol_page
	plugins /
		<= Selection $bog_selection
```

Исходником считается непустой `text()` вида: markdown у `$mol_text`, код у `$mol_text_code`. Свой компонент подключается тем же способом, достаточно объявить у него `text`:

```tree
$my_log $mol_list
	text \
```

Точечно: плагин с явным `text` в дереве самого компонента. Тогда искать ничего не нужно, в буфер уходит этот текст, выделяется узел хозяина.

```tree
$my_article $mol_text
	plugins /
		<= Selection $bog_selection
			text <= text
```

Плагин объявляется в дереве того компонента, чей узел он охраняет: у `$mol_plugin` хозяин — это owner, а не тот, в чьём `plugins /` он лежит.

## Как работает

Два статических слушателя на документе: `keydown` и `copy`. По Ctrl+A плагин ищет ближайший `[bog_selection]` вокруг каретки, а без выделения — вокруг фокуса. Внутри `input`, `textarea` и `contenteditable` не вмешивается. От хозяина плагин спускается по `sub()` только через уже отрисованные виды (`$mol_wire_probe`, узлы не создаются) и берёт первый сверху, чей узел содержит каретку и чей `text()` непуст. Если такого нет, Ctrl+A работает как обычно.

Найденный вид выделяется целиком через `selectAllChildren`, текст пишется через `navigator.clipboard.writeText`. Если следом нажать Ctrl+C, слушатель `copy` видит, что выделен весь вид, и подменяет данные буфера на тот же `text()`. Ничего не дорендеривается, поэтому у виртуализованного `$mol_list` в буфер попадают и строки за пределами окна, а выделение честно показывает только отрисованные.

Портировано из PR [hyoo-ru/mam_mol#888](https://github.com/hyoo-ru/mam_mol/pull/888), там плагин вешается на каждый `$mol_text` и ничего не выделяет.
